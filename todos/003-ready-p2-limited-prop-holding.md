# 居民有限手持展示

## Problem Statement

生成物件已经能领取和摆放，但居民还不能把合适的小道具真正拿在手里展示。用户说“拿着看看”时，当前世界缺少同一物件身份、手部挂接、放回和重进规则。

## Findings

- 现有物件身份、尺寸、布局事务和渲染资源应继续复用，不能创建第二份手持模型。
- 首期只适配一个当前居民、右手、一个固定展示姿势；精确抓取、双手、战斗、任意角色自动适配后置。
- 手持与摆放必须互斥；换角色、停止、换世界和重进不能产生复制品或悬空残留。
- 咖啡机体积不适合作为默认手持验收物；需要按尺寸和用途明确拒绝。

## Proposed Solutions

1. 在原世界物件状态增加有限挂接事实，显示层读取当前角色右手骨矩阵并乘以可保存的局部偏移；本批采用。
2. 只在画面层临时叠加一个模型；状态简单，但重进、工具和摆放会失真，不采用。
3. 完整角色装备与抓取系统；范围过大，后置。

## Recommended Action

按许愿机计划任务 4 执行一个窄闭环：一个当前居民、右手、固定展示姿势、一个尺寸合适且已拥有的道具。界面和居民正式工具共用事务；拿起时保留放回位置，停止或明确放回恢复原支撑面。无合格手骨、物件过大、换角色或旧轮迟到时拒绝并保持原状态。

## Acceptance Criteria

- [x] 失败测试先覆盖右手局部挂接、尺寸缩放后的偏移、摆放与手持互斥。
- [x] 一个已适配居民可拿起一件合适道具；画面每帧跟随实际右手骨。
- [x] 拿起、放回、停止、换世界、换角色和保存重进不复制、不遗留。
- [x] 过大物件、缺失右手骨、未知物件、过期版本和迟到结果明确拒绝。
- [x] 用户入口与居民工具共用同一服务和权限边界；后台不能自行拿走物件。
- [x] 无宿主测试、离屏渲染、规格与质量复核、单路整包构建通过。
- [x] 不声称精准抓取、双手、战斗、物理交互或任意角色兼容。
