# 生成物件摆放增量

## Problem Statement

已生成物件能够悬浮在许愿机并登记领取，但还不能正式摆放、移动、旋转、收回和保存重进。

## Findings

- 已有 `WorldState.objectStates` 与原子世界快照，可复用为唯一布局记录。
- 当前 GLB 输出固定在托盘；变换更新需要与资源加载分离。
- 固定导航图不能自动绕开家具；候选位置必须保留既有路线及活动入口净空。
- 真实 Marble 碰撞接管时只叠加点唱机，遗漏托盘碰撞，需同步修复。

## Proposed Solutions

1. 沿用世界状态，增加小范围布局提交、可靠支持面及同源显示和碰撞；本批采用。
2. 完整房间编辑器、任意网格支撑与动态导航；工作量大，后置。

## Recommended Action

执行既有许愿机计划任务 2／3 的摆放增量，先批准一块地面和一张独立展示台。用户操作与居民工具共用服务；后台默认无修改布局授权。至多四件同时摆出，其他留在物件库。手持、网页、交易和完整装修不在本批范围。

## Acceptance Criteria

- [x] 正式领取后按稳定身份登记，重复登记不复制；源模型不变。
- [x] 预览、摆放、移动、旋转、收回、一次撤销和保存重进通过无宿主测试。
- [x] 独立布局版本、幂等请求及保存失败原状态保留；渲染和碰撞同步。
- [x] 支撑面、人物占位、物件碰撞、路线与活动入口检查。
- [x] 收起式编辑入口；取消、关闭、失焦、换世界和聊天焦点隔离。
- [x] 居民能读物件、查表面、预览、提交、收回及撤销；停止后禁止迟到变更。
- [ ] 规格及代码质量复核；单路低负载测试和无签名整包构建。
- [x] 记录实际验证范围；不冒充已安装或应用内视觉验收。
