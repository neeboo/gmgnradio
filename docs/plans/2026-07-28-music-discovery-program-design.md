```text

              │
```

## 流媒体账号

`MusicAccountSession` 统一表达连接、断开、授权状态和能力检查。具体授权流程留在平台适配器：

- Apple Music 使用系统 MusicKit 授权，检查订阅、曲库读取和播放能力；
- 使用 OAuth 的平台通过浏览器完成带 PKCE 的授权码流程；
- 访问令牌和刷新令牌只保存在钥匙串；
- 歌曲、歌单和播放历史的可搜索元数据进入本地索引；
- 未登录、授权过期、权限不足或无法播放的来源不参加搜索；
- 授权失效不打断已经播放的本地歌曲。

账号连接成功后先做一次能力探测，再分页同步收藏、歌单和最近播放。以后使用游标增量同步，避免每次启动全量请求。

接入某个流媒体平台之前必须单独检查开发者条款、商业播放限制、广播限制和音画联动限制。接口可用不等于产品形态获得授权。

首个流媒体适配器优先验证 Apple Music。它在 macOS 上有原生授权、曲库请求、全库搜索和应用内播放器，和当前 Swift 架构一致。Spotify 暂不作为首发来源：其开发者政策页面当前明确提示商业流媒体应用、非交互广播和音画同步存在限制，必须先完成产品形态与条款审查。

参考：

- [Apple MusicKit 授权](https://developer.apple.com/documentation/musickit/musicauthorization)
- [Apple MusicKit 曲库请求](https://developer.apple.com/documentation/musickit/musiclibraryrequest)
- [Spotify 带 PKCE 的授权码流程](https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow)
- [Spotify 最近播放接口及政策提示](https://developer.spotify.com/documentation/web-api/reference/get-recently-played)

## 统一候选

所有来源归一成 `MusicCandidate`：

- `id`：来源内稳定歌曲标识；
- `canonicalID`：ISRC 等跨来源录音标识，用于去重；
- `source`：本地或流媒体；
- `title / artist / album / duration / releaseYear / genres`；
- `isPlayable`：当前账号、地区和设备下能否播放；
- `matchScore`：本次自然语言搜索匹配度；
- `userAffinity`：收藏、完整播放、主动点播等长期偏好得分；
- `energy / moodTags`：节目能量曲线与情绪匹配依据。

统一搜索并行查询所有就绪来源。相同录音只保留一个版本，优先选择本次匹配更好、用户偏好更高且确实可播放的候选。

## 节目单

节目规划器接收 `ProgramBrief`，包含目标时长、情绪标签、能量曲线、交谈模式、即时用户指令、屏蔽歌曲和最近跳过歌曲。

第一版的硬规则：

1. 只选择当前可播放歌曲；
2. 屏蔽和最近跳过歌曲不进入当前节目；
3. 同一艺人至少隔开一首，候选充足时隔开两首；
4. 一次规划 5–8 首，约 20–40 分钟；
5. 每播两首触发滚动重排，只替换未播放部分；
6. 相同输入使用稳定标识做确定性排序，便于复现问题。

软排序由搜索匹配度、用户亲和度、情绪重合度和目标能量距离共同决定。后续可以加入节拍、调性、年代、熟悉度、新鲜度和显式内容规则。

## 主持感

每个节目槽位都生成 `ProgramHostHint`。实时模型在切歌前收到：

- 当前歌曲和下一首歌曲；
- 选择这首歌的原因；
- 艺人、专辑、发行年份和风格等可核验事实；
- 本次转场要提亮、放缓还是延续；
- 这次是否该开口，以及最多说几句。

用户说“少说点”后，当前节目立即进入克制模式。默认只保留必要开场或重要转场，提示仍然完整，模型可以选择沉默。这样主持感来自节目意图和准确的信息，不依赖频繁说话。

模型可以提出搜索、换队列、播放和跳过等工具调用，客户端负责验证歌曲仍然可播放，并以本地播放器状态作为最终结果。
