## 一、两个模式，分期开放

| 模式 | 用户需要做什么 | 系统交付 | 排期 |
| --- | --- | --- | --- |
| 简单模式：许愿机 | 提供或选定一张图片，确认大致尺寸与用途 | 一个可预览、摆放、保存、下载的成品外形；具备条件时可手持或绑定现有活动 | 当前首版 |
| 高级模式：建造 | 向 Agent 描述目标，逐步确认设计；可以调整零件和组装方案 | 设计源文件、命名部件、尺寸、装配关系、运动限制及可用 GLB | 后续迭代，不阻塞首版 |

简单模式允许形状不完全准确、背面不完美。首要目标是门槛低、反馈快、电脑能运行、用户愿意把自己的想象带进房间。生成不理想时允许不采用，保留原图和结果作比较，不强迫用户进入专业建模工具。

高级模式以后可以查找有权使用的设计图、分解需求、制作 CAD 零件、测量、装配、渲染检查并修改。用户仍通过自然语言引导，精细参数按需展开。研究模型、CAD 和机械仿真都属于可替换的制作工具，不改变普通用户的入口。

## 二、许愿机是空间中的创作入口

许愿机是生活舱里真实存在的开放式制造托盘：低底座、承托盘面与简洁状态灯，盘面上方留空。完成的真实物件模型悬浮在托盘上方，居民可以走近领取。无需制造柜、封闭舱体、顶盖或复杂机械动画。托盘与产物是独立对象，产物按采用尺寸显示，不能用发光占位物冒充已生成的模型。

- 主入口是同一居民聊天：用户给图片并说明要求，由居民调用工具提交异步任务。
- 点击托盘可查看任务和产物状态；辅助面板可以收起，关闭面板不丢失后台任务，不要求用户另开生成器完成主流程。
- 用户只有一句愿望时，Agent 可寻找参考图；具备图片生成工具后，也可提出原创参考图。先展示所选参考及来源，用户确认本次生成和用量，再提交。
- 居民可以建议制作物件，但默认无权因自主活动发起收费生成。以后用户可设限定预算和委托范围；不逐件打断已有明确授权的批次。
- 生成期间居民可以继续生活，机器显示简洁进度，不要求用户一直盯着倒计时，不假装模型已开始或精确知道剩余时间。

首版最小流程：

```text
给居民图片，说明尺寸与用途
  → 居民通过工具提交异步生成任务
  → 居民继续生活，任务后台运行
  → 完成事件送达原居民，真实物件悬浮在托盘上
  → 居民走到托盘领取
  → 正式领取成功，转为已拥有物件
  → 摆放／在已支持角色上试持
  → 保存、截图或下载
```

“生成成功”“托盘待领取”“领取成功”“已摆放”“居民实际使用”分别显示真实结果。生成成功不代表已经领取；领取需要居民真实到达和正式工具回执。未到达、用户中断或暂停时保留待领取产物；重复通知与领取重试不复制物件。完成事件关联原世界、居民与任务，不冒充人类新消息绕过暂停。失败后由通用 Agent 循环根据原因继续查询、修正或向用户报告；不写死问答，不自动无限重试或重复消耗额度。

## 三、尺寸、摆放与手持

### 3.1 尺寸采用可理解的表达

普通用户先选“桌面摆件”“落地物件”“手持道具”，再看默认尺寸；允许说“像杯子那么大”“总长一米二”，也可直接输入厘米或米。默认值必须标为建议，不能冒充从单图测得的真实尺寸。

模型出来后，预览中放一个居民轮廓或尺寸标尺。用户可选要控制的长、宽或高，保持整体比例缩放；保留源模型，另存采用的变换，不因反复预览累乘缩放。

现有服务字段 `height_meters` 仅表达建议高度，不可拿它表示倾斜长剑的总长。首版加工层需记录被选尺寸轴、目标米制长度、上轴、正面与底部／支撑点，再输出已校准包。此能力需新增和验收，不能因接口已有尺寸字段认为已实现。

### 3.2 先摆放，再做有限手持

- **V1-A 必须完成：**独立模型预览、地面／指定桌面摆放、移动、旋转、收回、保存重进。使用少量可靠支持面，无需等完整房间编辑器。
- **V1-B 可玩增量：**一名已适配居民、单手持物、一个经校验的展示姿势，提供“拿着看／放回”。优先一把剑形道具或杯子。与 V1-A 采用同一个物件身份。
- 手持需要握持点、朝向和模型到手骨的局部变换。自动建议只作初值；提供“向前／后、上／下、旋转”的可视微调，并保存为该物件与该角色的适配。
- 缺少适配、握柄不清楚或物件过大时保留摆放功能，说明暂不支持手持。不让首版等待任意 VRM／PMX 的手指贴合、双手大剑、挥砍碰撞或战斗系统。
- 手持时物件从原摆放状态转为挂接状态，放回后恢复指定支持面；取消、换角色、换空间和重进不能产生复制品或遗留悬空物件。
- 装饰、手持展示、可使用设备分开标注。剑形道具不自动拥有战斗能力；咖啡机外形不自动拥有冲煮结构。只绑定已支持的动作与场景接口。

普通道具交付 GLB；VRM 用于有相应骨骼与表情规范的角色，不把图片生成的人形外观默认标成可用 VRM。

## 四、从入口到商业服务，逐步开放

| 版本 | 开放内容 | 暂不要求 |
| --- | --- | --- |
| V1-A：空间许愿机 | 聊天交图、居民工具委托、异步任务与完成通知、托盘悬浮产物、到达领取、尺寸确认、个人库、摆放保存、下载与分享 | 公共网页、支付、商家、CAD、手持通用化 |
| V1-B：居民试用 | 参考选择扩展、有限单手试持、已有能力绑定、日常内容分享 | 任意角色自动适配、战斗或物理装配 |
| V1-C：网页与展示 | 网页上传生成、查看任务、在线预览、下载；公开物件页提供客户端入口，安装后可找回已保存物件 | 完整 C2C 交易系统、可进入的公共房间 |
| V2：小规模素材经营 | 生成额度或加工收费、创作者上传、精选目录、购买与授权下载、分成和下架 | 大型电商系统、全量商家自动入驻 |
| V3：高级建造 | Agent 查设计参考、规划零件、CAD／其他工具建造、拆装预览、验证后导出 | 所有物件都达到真实制造精度 |

上表为交付顺序，无虚构上线日期。V1-A 验收后即可发布试玩增量，后面各阶段不成为它的发布前提。网页可以先服务下载和传播，让未安装客户端的人也能看见、制作和获取物件，再自然引导进入空间。

### 4.1 同一服务，多处入口

许愿机是空间里的呈现，制作面板、聊天和网页复用同一任务身份与个人素材记录。网页和客户端不维护两套互不相认的库存；已有产物可以下载和导入，不因换入口再次生成或收费。

先保留两个导出层次：普通 GLB 供通用工具查看；空间物件包附尺寸、来源、预览、支点及已验证用途。普通 GLB 单独下载不保证在其他软件里保留我们的活动能力。公开包不包含用户模型密钥、会话、私人记忆或未获许可的音轨。

### 4.2 商业化边界

- 生成／加工服务费用、买现成素材的价格、后续空间租金、居民思考与语音用量分别说明。生成额度与语言模型 Token 包分开计量，用户应能理解买到什么。
- 先记录真实排队、生成、加工与采用成本，再确定报价。提供清楚的预估、确认、失败处理和请求幂等；不在此计划中承诺“失败一定不产生供应商成本”。
- 个人使用与商业空间使用沿用两档授权；能否修改、分享录像、下载源文件、再分发或再售卖另列。公开上传默认关闭，由用户明确选择发布。
- 网络可找到的图片和模型不等于有权上架。月光大剑等已有 IP 可以作为需求示例，演示与出售须分别核对权利；商城样品优先自有或明确获授权设计。
- 商家／创作者上传的素材按相同导入标准检查，不执行其附带程序。支付上线前才增加订单、授权交付、退款、分成和投诉下架的必要流程；不提前建设复杂经济系统。
- 当前 DGX API 是私有试验服务。网页公开前必须完成身份与任务隔离、用量限制、下载授权及私有输入保护，不将现有共享凭据暴露给浏览器。

- V1-C 开工前确定网页放置项目、账号和服务隔离方案，不在本轮新建前端工程。网页只通过受控服务提交和下载，不能携带共享管理员凭据。
- 首个网页验收是“非客户端用户看见物件 → 预览 → 下载 → 客户端导入”，随后补网页生成；付款与商家上传另设 V2 验收。

## 七、首个试玩验收

1. 用户在现有生活舱给居民一张有权使用的单物体图片，描述要求。
2. 居民通过工具提交任务，保留尺寸、用途和本次用量；期间可继续聊天或活动。
3. 完成通知送到原居民，真实产物按采用尺寸悬浮在开放式托盘上方。
4. 居民真实走到托盘并领取，再放在指定支持面；没有对应能力时不虚构使用。暂停或无法到达时保留待领取物件。
5. 收回、再摆放、重进空间，尺寸、朝向、数量与材质保持正确。
6. 下载结果，并通过一张空间截图分享这次愿望；未公开的原图和私人对话不随导出泄漏。
7. 验证一次失败、一次重复提交和一次未采用结果；没有重复生成、重复物件或无法解释的扣费状态。

V1-A 满足以上即可交付试玩；V1-B 再增加居民拿持并放回的验收。正式产品指标先看生成后采用率、从图片到首次摆放的步骤与耗时、下载分享率、次日回访，以及单个采用物件的实际成本。没有数据前不设虚构的成功率或最低配置承诺。

## 八、本轮分阶段验收与表现要求

1. **输入与委托：**空间和 Live Cam 的现有聊天支持选择、粘贴图片，图片与文字进入同一居民会话。无法发送时保留输入与附件；取消附件、关闭面板或普通聊天都不自行触发收费生成。服务配置不触发钥匙串解锁。
2. **后台任务：**居民正式工具提交后可以继续对话或生活。关闭面板、重复点击、重新连接及网络失败不重复生成；完成与失败状态来自真实服务返回。未完成任务的恢复、取消和费用提示分别检查。
3. **完成与领取：**真实 GLB 下载并成功加载后才能显示待领取产物；低托盘保持开放，按确认尺寸显示物件。完成事件只能送达原世界与原居民，暂停和中断仍有效。居民到达领取点、正式领取回执和拥有状态必须一致，不能由台词替代。
4. **动作与思考：**居民的骨骼动作扩展与真实思考状态表现沿用居民主路线，不在许愿机内另造一套。优先级为正式世界行走／活动、实际思考动作、空闲时选中的舞蹈。仅在实际模型运行处于思考状态时，可临时覆盖空闲期间用户选中的舞蹈；思考结束、失败或中断后恢复原选择，不以随机动作或持续思考姿态冒充模型工作。动作工作代理已核实本机安装 `gmgn.motion.ardy-backflip`（v1.5.0、VMD、`loop=false`）与 `ardy-natural-jumping-jacks`；后空翻仍缺正式工具／空间绑定和验收，不能因文件已安装便列为居民已会使用。新的 Bones 跑动／跨越素材受获取资格与许可限制，当前不新增下载。新增动作数量、适配角色和画面效果单独验收。
5. **交付记录：**分别记录无宿主合同测试、整合后完整构建、真实服务链路、宿主画面与安装结果。前两项通过只说明相应代码检查完成；后几项未执行时保持明确待验收，不将 V1-A 标成完成。
