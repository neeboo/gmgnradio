# 生活舱 01：首个 Living Space 房间设计

日期：2026-09-04

## 目标

把默认空间从示例厨房换成一个随应用安装、离线可用、低配置可运行的宇宙生活舱。它首先是 Agent 的住处：用户可以观察它生活，也可以通过聊天让它在房间里活动。

首版只验证三件事：

- 用户一眼看懂这是一个可以长期居住的舱室；
- Agent 能感知房间里的地点，并能走过去、坐下、观察或听音乐；
- 固定舱体和可交互物件分开表达，为以后替换、交易和空间分享留下接口。

## 空间布局

房间采用开面舞台式构图，镜头从舱室前方看进去，避免狭小房间遮挡角色。

| 区域 | 物件 | 首版行为 |
| --- | --- | --- |
| 左后 | 睡眠舱 | 走近、坐下休息 |
| 右后 | 工作台与控制台 | 走近、查看设备 |
| 右侧 | 点唱机 | 点歌、听音乐、跳舞动作入口 |
| 左侧 | 咖啡机 | 走近、操作动作入口 |
| 左舷 | 观景窗 | 看星空 |
| 后舱壁 | 气闸门 | 观察、作为以后连接新空间的入口 |

中央保留连续可走区域，避免家具切碎寻路。出生点放在前部中央，让用户进入空间后先看到 Agent，再看到完整舱室。

## 视觉原则

- 深灰舱体、暖琥珀生活灯、少量青色设备灯；
- 用圆角舱门、结构肋和观景窗表达飞船感，不堆复杂机械细节；
- 床垫、矮桌、杯子和一株植物提供生活气息；
- 使用少量 SceneKit 基础几何体，不依赖网络下载，也不依赖高模和大贴图；
- 全景只在空间模式显示，Live Cam 仍保持透明桌面角色。

## 技术边界

- `gmgn-living-pod-v1` 是本地空间，不走 Marble 的 SPZ 下载流程；
- 世界事实仍来自 `world.json`，包含碰撞、路径点、活动点和镜头；
- 本地低模画面只是表现层，不能直接修改 Agent 位置或世界状态；
- 咖啡机、点唱机、工作台、床和气闸门具有稳定节点名，后续可替换成独立 GLB；
- 旧厨房包保留为工程参考，不再作为应用默认房间。

## 首版验收

- 默认世界包是 `living-pod-v1`；
- 进入空间无需 Marble 网络资源即可显示完整生活舱；
- PMX 和 VRM 角色都能与生活舱同时显示；
- 世界包校验通过，活动入口均能从出生点到达；
- Live Cam 不绘制舱室；
- 房间工厂至少产出睡眠舱、工作台、点唱机、咖啡机、观景窗和气闸门六个稳定节点。
