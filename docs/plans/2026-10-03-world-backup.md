# 世界备份与未来引擎恢复

## 决策

用户决定第一步不替换跨平台引擎，先建立世界备份；将来替换引擎时可以 recover。
当前 Swift/Metal 客户端与 taskd 权威保持不变。独立 Bevy 原型仅保留为对照，不继续扩展或迁移。

## 第一阶段范围

- 备份世界权威状态、对象摆放/尺寸/启用状态/功能元数据，以及可定位的原始资产。
- 同时保留可供未来客户端消费的版本化 JSON、资产相对路径、大小与 SHA256 清单。
- 世界包的 SPZ、GLB、人物、动作与贴图等通过明确资产根纳入，不能只保存当前引擎缓存。
- 不包含 Keychain、环境文件、账户凭据、代理会话或整个应用支持目录。
- 恢复先进入新的隔离目录；校验失败不接受为成功备份，禁止覆盖用户现有世界。
- 备份是归档，不增加第二套正在运行的世界状态写入者。

## 真实边界

当前世界唯一写入者是 gmgn-taskd；Swift 的旧 state.json 已退休为只读预像。
现有 world-dump 提供状态投影，world-import 是一次性旧世界导入，两者均不能单独代表完整资产备份和迁移恢复。
第一阶段优先提供可验证的离线归档和恢复暂存工具。当前应用的一键恢复入口、未来引擎导入适配器需单列验收，不能以文件解包成功代替。
引用到的缺失资产必须报告；未显式纳入的人物与媒体配置也必须说明，不得声称完整。

当前已确认的持久化缺口：GMGNRadioApp 的 WorldScreenStore.Source 接线中 persistDefinition / persistContent 仍为 nil，屏幕标定与内容可能只存在当前会话内。仅备份数据库无法补出这部分未保存的数据，必须在后续产品备份入口前修复或明确提示。

世界快照与权威历史恢复分层：首版中立快照保留全部 world_records 与包来源，不将旧幂等请求、消费游标和未完成任务重新激活；完整权威审计历史归档和当前客户端恢复适配另列工作。人物包和动作包要连同 manifest、贴图、附属文件及选择记录保存；世界缓存中仍被引用的 SPZ/collider 不能依赖缓存永远存在。

## 验收

1. 构造真实世界记录及 SPZ/GLB/动作等样本文件。
2. 创建备份，验证每个文件与状态清单。
3. 在另一个根目录恢复，不再依赖源文件绝对路径。
4. 比较世界记录、摆放与功能配置，以及全部纳入资产的字节哈希。
5. 损坏、缺失文件、路径穿越与已有目标目录必须拒绝。
6. 用户真实世界备份与当前应用恢复需另行记录，不用 fixture 结果替代。

## 第一版结果

新增 `tools/world-backup/world_backup.py`，提供 backup / verify / recover 三个命令，使用 Python 标准库。独立复跑 `python3 -m unittest discover -s tools/world-backup -p 'test_*.py' -v`：12 项通过，exit 0，包含源 fixture 删除后的不同目录恢复和完整性/路径负测试。
首版保守纳入全部 world_blobs，孤立或远端未下载的 blob 也可能阻止备份；资产根需显式指定。原始状态中的本地路径保留，通过 referenceBindings 提供包内路径映射，后续客户端适配器需消费映射。未做用户真实世界备份，未接当前 App 的恢复入口。
