# 空间装修与居民安置：设计草案

日期：2026-09-06

状态：设计研究，尚未实现，也未做真机交互验收。

归属：居民自主行动主线的扩展要素；不阻塞当前自主循环的开发。

## 1. 要实现的体验

观察时，空间仍然安静，居民照常生活。用户点击右下角的“装修”，才出现物件托盘；点一把椅子，在地板上放下，转一下方向，再回到观察。居民随后能够走到新位置坐下。这就是首个完整验收，先于完整装修系统。

居民也可以帮忙：“把这两把椅子摆到窗边，留出走路的位置。”它查看现有物件和可放区域，提出有预览的方案，在获得委托的范围内执行，再检查新位置是否真的可用。仅说“已经摆好”不能算完成。

本草案采用三个假设：首期仍是一名居民；空间主体继续使用 Marble，家具作为独立模型；首期只处理已经导入和拥有的物件。购买、素材市场、房屋结构编辑和引擎迁移均不在本轮范围。

## 2. 当前代码核对

以下结论来自当前工作树的只读检查，不能代替真机验证。

| 能力 | 已有事实 | 尚缺部分 |
| --- | --- | --- |
| 物件变换 | `WorldObjectState` 有启用状态、`WorldTransform` 和元数据；变换包含位置、四元数、缩放 | `WorldSimulation` 没有正式物件变更方法；不能据此认为物件能编辑 |
| 独立物件表现 | `MarbleSpatialView.drawMarbleJukebox` 把独立点唱机节点叠加到 Marble；位置和朝向取自 `MarbleLivingCabinPresentation` | 通用物件实例表、模型加载与生命周期、预览层；当前入口仍为生活舱专用 |
| 物件感知 | `currentResidentWorldContext` 从活动的 `propIDs` 枚举物件，尝试读取 `objectStates` | 未绑定活动的装饰物不能完整呈现给居民；需要按真实实例列表读取 |
| 碰撞 | `GLBColliderDecoder` 解码网格并处理坐标变换；`MarbleLivingCabinCollisionWorld` 合并环境与家具阻挡；`ReplaceableCollisionWorld` 可替换查询实现 | 通用可移动物件碰撞投影、摆放支持面、出口净空和提交前检查 |
| 选择物件 | 已有窗口层 `hitTest` | 没发现通用三维物件射线拾取接口；窗口命中不能选中家具 |
| 摄像机输入 | `StageWorldInteractionView` 的鼠标拖动控制镜头，滚轮推进镜头，W/S 沿视线前后，A/D 横移，双击复位 | 编辑模式的输入分流、表面拖放、触控板手势与物件操作互斥 |
| 导航 | `WaypointNavigationGraph` 根据包里的路点和路线生成固定图；碰撞查询能检查一段路径是否可通过 | 家具移动后路点入口更新、受阻边检查与当前行动重新规划；现有图不会自动绕开新家具 |
| 活动锚点 | `WorldActivityAnchor` 有变换、入口路点、动作和关联物件 ID | 以物件为父节点的局部锚点；现在不能假设搬椅子会带着坐姿和入口一起移动 |
| 存档 | `WorldState` 有世界版本和物件状态；`AtomicJSONWorldStatePersistence` 使用原子文件替换 | 布局命令、撤销记录、布局版本、各运行投影共同采用同一版的发布流程 |

## 3. 三条实现路径

| 路径 | 用户操作 | 优点 | 代价与边界 |
| --- | --- | --- | --- |
| A：表面吸附的轻装修，推荐 | 选中、拖到地板或桌面、旋转、放下 | 适合鼠标和触控板；不必理解三维坐标；可以逐步扩展 | 要先准备支持面、占地轮廓和活动空间 |
| B：自由三维操纵器 | 用三轴箭头和旋转环调整所有自由度 | 精确，适合技术创作者 | 控件密集，容易悬空、穿墙；不适合作为默认体验 |
| C：居民直接全自动装修 | 提一句要求，居民给出并应用布局 | 操作最少，符合陪伴方向 | 仍依赖 A 的位置协议和预览；当前缺少可靠布局数据，不能独立先做 |

推荐先做 A，随后让 C 使用同一工具。B 只保留为远期“精细调整”的可能性，首期不实现。The Sims 4 官方说明采用建造模式、选物件、旋转、放置的步骤，并提供离散旋转和自由旋转；本项目借鉴这种操作层次，不照搬其所有快捷键。[EA 官方物件旋转说明](https://help.ea.com/en/articles/the-sims/the-sims-4/how-to-rotate-sims-4/)

## 4. 默认安静，装修时才出现工具

观察模式不显示网格、包围框、坐标、轴线或永久物件清单。右下角菜单新增一个“装修”入口，与聊天、播放器、空间设置分开。

进入后保留当前视角，可点“看全房间”切到房间作者提供的装修镜头。不要自动飞行转场，也不从脚边突然跳到高空。底部出现单行托盘，首期仅“房间里”和“我的物件”两个入口，缩略图配名称；选中物件后才出现旋转、收回、撤销等小型操作栏。

临时预览用半透明模型、细轮廓和稳定的接触阴影。可放时显示落点与朝向；不可放时显示占用区域和一句原因，如“这里挡住门了”。颜色之外同时提供文字或图标，避免仅凭红绿辨认。只高亮当前关联区域，不让整个空间闪烁。

静态场景里烘焙的家具不显示可选轮廓。托盘明确区分“可移动物件”和“场景背景”，避免用户尝试拖动 SPZ 中的一把椅子却无响应。新空房模板尽量只生成固定壳体和环境，将可改造部分留给独立素材。Marble 官方将碰撞网格与视觉表示分开，碰撞网格适合简单物理且不用于最终视觉表现；它不能直接提供可编辑家具目录。[World Labs 网格导出说明](https://docs.worldlabs.ai/marble/export/mesh)

## 5. 操作规则

| 操作 | 首期默认 | 细节 |
| --- | --- | --- |
| 选择 | 点击独立物件，或在托盘点缩略图 | 小物件难点中时可从“房间里”列表选；优先最近可见命中，不穿墙选物件 |
| 移动 | 按住物件拖放；也支持点“移动”后跟随指针，再点击确认 | 后一种适合触控板，避免长时间按压；拖放过程只修改预览 |
| 旋转 | 物件旁提供左转、右转按钮，默认每次 45° | 拖动平面旋转环可连续旋转；逗号、句号为可选快捷键，界面操作完整可用 |
| 吸附 | 支持面、相邻边缘和低密度网格辅助对齐 | 按住 Option 暂停对齐，松开恢复；工具条也有吸附开关，不依赖键盘 |
| 调整镜头 | 装修模式中拖动空白区域转镜头，滚轮保持已接受的缩放方向 | 物件拖动期间镜头不转；空间键按住拖动作为可选镜头操作；不把滚轮同时用作旋转 |
| 触控板 | 单指点击或拖物件；双指滚动继续缩放；捏合可与缩放归一 | 镜头手势进入时锁定当前物件预览，结束后重新投射落点；托盘上的滚动只滚列表 |
| 键盘焦点 | 聊天或搜索有焦点时，WASD 和物件快捷键都不生效 | 指针在操作栏、托盘时不透传空间点击；松键、失焦、退出时清理按键状态 |
| 取消 | Escape 或“取消摆放”回到上一个正式位置 | 退出装修不丢失已经成功提交的摆放；当前未落下的预览直接取消 |
| 撤销、重做 | 可见按钮以及 Command-Z、Shift-Command-Z | 一次拖放算一次操作，一次居民批量方案也算一次；不按每帧存历史 |
| 保存 | 每次成功落下即提交并保存，右上角显示“已保存” | 保存失败保留可重试的预览，正式状态维持原样；关闭窗口取消未提交预览 |

首期装修时暂停居民的空间移动与物件活动，并冻结自动运镜，界面显示“装修中”。音乐可继续播放。完成后恢复行动调度，按新布局重新观察和规划，不能直接继续沿旧路线走。后续可缩小为只暂停受影响物件与区域，暂不引入复杂并发编辑。

## 6. 地面、墙面和桌面

模型素材需要最少的摆放描述：标准米制、底部支点、占地轮廓、允许承载类型、局部碰撞体、交互锚点。导入时做一次尺寸确认，正常装修不提供随意缩放家具，避免再次出现门与角色比例失真。

表面具有稳定 ID、局部变换、有效边界和类型：地面、墙面、桌面。拖放以相机射线命中表面，按模型支点投射位置；附近有多个表面时保留当前承载面，显式切换目标，防止杯子在桌面和地面间跳动。

- 地面：以批准的地面片区支撑家具，不把任意网格三角形都识别成地板。桌脚和小台阶不应让家具突然悬空。
- 墙面：只允许声明可挂墙的物件，吸附墙面法线；需要单独的挂点与高度控制。首期不修改墙、门或窗。
- 桌面：杯子等物件落在桌面有效边界内，依照支点对齐表面；桌面需要独立模型或作者声明的稳定表面。
- 桌子连同杯子：记录父子承载关系和局部位置；搬桌子时整体计算孩子变换，以一个批次验证和提交。首期不允许把有孩子的承载物单独收回，需明确整体收回或先移走杯子。

Marble 的生成结果不能直接保证尺度、平整支持面或家具语义。早期允许作者标记少量地板、桌面和出口区域；没有可靠支持面时显示“这里暂时不能摆放”，并提供其他可用区域，不伪造识别结果。

吸附关闭只改变对齐方式，不关闭穿墙、出界、支撑和出口检查。模型极简碰撞体与视觉外观有差别时，预览以实际占地提示。相邻物件的装饰细节可按素材标注允许接触，居民身体与使用区域仍不能被占据。

## 7. 同一个布局提交协议

用户拖放和居民工具都调用同一个 `WorldLayoutService`（拟新增）。界面不能直接保存 SceneKit 节点坐标，居民工具不能直接修改 JSON。

```text
拖放／居民方案
      ↓
临时布局预览（不影响正式空间）
      ↓
校验位置、支撑、碰撞、出口、活动入口及委托范围
      ↓
准备同一版的渲染节点、碰撞查询、导航入口和活动锚点
      ↓
原子保存新布局及撤销信息
      ↓
在同一主线程发布点替换正式快照，解除受影响行动暂停
      ↓
返回已提交版本与真实位置；居民重新观察并使用物件
```

拟增加 `layoutRevision`，与现有频繁变化的世界 `revision` 分开。时间推进、聊天、镜头变化不能让正在摆放的方案每帧过期；其他人或居民修改布局则必须使旧方案过期。命令携带世界 ID、预期布局版本和幂等请求 ID。批量操作全批成功或全批保留原样。

候选布局先准备派生对象，再保存，再同步发布。准备或保存失败不产生正式成功回执；进程在保存后终止，重启从已保存布局重新构建所有派生数据。运行时使用布局快照引用统一取得渲染和空间查询，禁止渲染已经移动、碰撞仍留原地的跨版本运行。初版不需要独立服务器或复杂分布式事务。

已有 `objectStates` 可承载实例状态，但包还要增加物件原型与初始实例定义：资源引用、碰撞、支持面、局部活动锚点和占用空间。资源与实例分开，多个椅子可复用同一模型；用户布局单独保存，包版本升级不会覆盖用户摆放。旧包继续按原本固定布局运行，只有完成描述的物件开放编辑。

位置换算只做一遍：素材局部空间 → 物件变换 → 统一米制世界空间。渲染再应用既有视觉校准；导航、碰撞和交互全部使用世界米制坐标，不能各自另乘缩放。

### 导航的最小做法

第一阶段沿用固定路点图，重算物件入口，检查候选布局下必经路线与活动区域。如果移动导致原图不可达，就在预览阶段拒绝，并建议仍可达的落点。这种限制需要明示，不能宣称已有自由绕路。

下一阶段引入小房间的二维可走网格或可重建局部导航；先按房间尺寸和居民胶囊离线测试开销，再决定实现。依赖 `WorldNavigationRouting` 接口即可，不为装修迁移整套引擎。

出口检查既包含作者声明的门前净空区，也包含居民当前位置到出口的路径可达性。只检查桌子是否与门重叠，无法避免家具形成围墙。活动还要校验坐下、起身、按按钮时所需空间。

## 8. 居民安置与设计

将“提议”和“执行”分开呈现。没有明确委托时，居民可以说“我想把椅子摆到窗边”，生成预览但保持现场不动。用户直接说“把这两把椅子放到窗边”即可授权这两件物件的搬动，不再要求每把椅子各确认一次。

委托范围只包含本房间、列出的现有物件、移动与旋转、指定保留区域和有效期。例：“整理桌面的杯子，其他东西别动”不能扩大为搬桌子。长期“你自己布置这个角落”可保存为用户可撤回的窄范围授权；默认自主生活开关不包含装修权限。

居民流程：观察房间与物件 → 找到受支持表面和空位 → 提出一到三个布局 → 校验并展示预览 → 在授权范围内提交 → 读取回执 → 到新入口尝试实际活动。遇到碰撞，读取具体原因并尝试其他候选点；只有缺少用户偏好或超出范围才问用户。几次候选均不可用时说明局部限制，避免无限重试。

首期布局采用确定性的平移或批量替换，不能宣称角色身体已经完成搬运。可以表现居民走近、查看、整理的动作；动作只是表现，布局事实仍来自正式提交。真正拿起和搬运需要抓点、动画和路径联动，放到后续素材能力中。

不会自动购买、删除用户资产、移出房间、移动固定壳体或阻塞出口。“收回”代表明确移到个人物件托盘，属于单独授权的操作；默认自动安置工具仅含位置和旋转。

### 工具接口草案

接口名称为设计候选，实施时复用现有工具会话注册、取消与回执机制，不另建聊天循环。

| 工具 | 输入概要 | 返回 |
| --- | --- | --- |
| `inspect_layout` | 世界 ID、可选区域、分页 | 布局版本、可编辑物件、真实尺寸与位置、锁定状态、活动入口、出口 |
| `list_placement_surfaces` | 可选物件 ID、区域、分页 | 支持面 ID、类型、边界、允许摆放类型；仅声明过的可靠表面 |
| `preview_layout` | 预期布局版本、物件变换批次、承载面 ID | 方案 ID、标准化落点、完整受影响物件、冲突原因和可用候选 |
| `apply_layout` | 方案 ID、幂等请求 ID | 已提交布局版本、事务 ID、变更前后位置、受影响活动；权限由宿主委托校验 |
| `undo_layout` | 事务 ID、当前预期布局版本 | 新的提交版本和恢复位置；版本冲突时重新读取，不覆盖后来的修改 |

`preview_layout` 无持久化副作用；不能产生模型口述“已完成”的依据。方案内容存在宿主，`apply_layout` 只采用同一方案，不能附带另一批位置或购买动作。`undo_layout` 是一条新的布局事务，也走碰撞、活动和存档检查。保留少量近期逆操作即可，暂不搭建通用无限事件回放平台。

错误按事实分层：`unsupported_surface`、`out_of_bounds`、`overlap`、`exit_blocked`、`activity_unreachable`、`layout_changed`、`outside_delegation`、`save_failed`。可恢复冲突返回关联物件或区域 ID；不把所有错误改成“请用户自己摆放”。用户中断后取消预览、禁止迟到提交；已经提交的操作不偷偷回滚，应明确显示并允许撤销。

## 9. 分阶段最小版本

### E0：一件物品真正移动

- 将独立点唱机从专用展示配置接到实例状态；验证它并未烘焙进背景。
- 一块批准地板区域，点选、拖动预览、左右旋转、确认、取消、一次撤销。
- 打通统一命令、碰撞、使用入口与存档；自由摆放以当前导航可达区域为限。
- 装修时暂停居民空间活动，退出后居民能走到新点唱机位置并使用。
- 一旦出现重启回原位、角色去旧位置、可穿过点唱机，就停在此阶段修一致性。

### E1：好用的小房间装修

- 三至五种已验证独立物件，托盘、接触阴影、吸附、触控板完整操作、连续撤销重做。
- 地面摆放稳定后加入一张桌子与杯子的承载关系；墙挂物单独一项验证，不同时扩展所有表面。
- 明确保存提示、不可放原因、编辑模式与聊天输入的焦点隔离。
- 物件导入只接收素材服务已验证输出，拒绝未知尺度、损坏模型和超预算资产，不在客户端现场重新生成。

### E2：居民帮助安置

- 接入上述查询、预览、提交工具与窄范围委托。
- 实现“帮我把点唱机转向沙发”“把两把椅子靠窗摆，门口留空”。
- 一次方案整体应用及整体撤销；用正式活动结果验证居民实际能用上新布局。

### E3：开放设计和更自由的摆放

- 局部导航更新、批量方案比较、更多墙面与桌面类型、分享布局差异。
- 有了素材动作和拿取抓点后再加入身体搬运动画。
- 创作者扩展物件描述；外部描述与模型返回均按数据处理，不能加入任意脚本、宿主工具权限或隐藏购买行为。

各阶段是依赖顺序，不预设工期。E0 可以在主线循环稳定后开始；素材服务、模型验证和编辑设计可并行，不能用它们替代居民自主行动验收。

## 10. 验收场景与体验目标

这些是待测门槛，不是已经达到的结果。

### 总验收：可玩、可自主、可仿真

三项需在同一个空间、同一个居民和同一个点唱机上串起来，分别展示三个孤立样片不能通过。

- 可玩：用户看得懂如何移动、旋转和摆放，操作有清晰预览、取消和撤销；点唱机仍能真实播放。
- 可自主：居民感知变化、自己规划并使用新位置的物件；遇阻先检查和调整，能接受人的引导或停止。
- 可仿真：实际位置、支撑、碰撞、路径、活动入口和存档遵守一致约束；居民说过的话与正式事件分开，重进后能读到真实留下的变化。

最低闭环如下。表中“已有”指代码基础已核对，整条运行链仍待验证。

| 步骤 | 已有基础 | 待补能力与通过条件 |
| --- | --- | --- |
| 用户移动点唱机 | 独立点唱机表现、物件变换数据结构 | 编辑器与正式布局命令；落下、旋转、取消、撤销都使用同一协议 |
| 居民感知新位置 | 居民观察上下文可读取物件状态 | 从正式实例表取得新位置与版本；不能继续读取生活舱旧常量 |
| 居民到达并使用 | 路点导航、活动锚点、点唱机播放能力 | 移动物件同步变更入口与动作锚点；检查真实到达和播放结果 |
| 路线受阻后重新判断 | 碰撞检查和通用 Agent 循环提供基础 | 返回准确阻挡信息并重新观察；当前固定路点只允许选择图中仍可达路线或合法落点，不声称可在任意装修布局下自由改路 |
| 人类引导或停止 | 循环具备引导与停止控制 | 编辑预览、布局提交及物件活动共同服从取消范围；不让迟到结果继续搬动或启动旧任务 |
| 重进后保留位置与真实经历 | 原子世界状态存档；物件状态可编码 | 重建相同布局与所有空间投影；补齐必要的已验证活动经历持久化与读取，不能把进程内近期观察或模型对话当作已持久化历史 |

最后一步至少保存“哪件物品移动到了哪里、居民实际用过它及对应结果”；失败和中断同样如实记录。长期全量历史与记忆检索可以后做，但重进之后不能只留下一个看起来相同的场景，居民却丢失这次已经完成的经历。

### 具体场景

1. 新用户不看说明，在一分钟内将点唱机移到指定区域、旋转并退出装修；五名测试者中至少四名完成，记录误拖镜头次数。
2. 仅触控板完成上述流程，无须记快捷键；托盘滚动、搜索输入和聊天不会推动镜头或物件。
3. 拖放预览不改正式状态；取消、失焦、切房间、窗口关闭后没有残留预览，也不会迟到提交到别的房间。
4. 在目标低配 Mac 上，拖动预览的端到端响应目标为 95 分位小于 100 毫秒；局部预览不重载 SPZ，记录进入装修前后帧率和内存增量，不以高配置机器单独通过。
5. 杯子放桌面不悬空，桌子移动时杯子保持相对位置；批次任何一件失败，所有物件保持原布局。
6. 放到门口、墙内、居民身体内或坐下区时显示具体冲突；临时关闭吸附也不能绕过这些检查。
7. 移动点唱机并重启后，视觉位置、碰撞、可走路径、按键动作入口、居民观察结果和存档位置一致。
8. 居民按明确委托搬两把椅子，不动其他资产；遇阻能换合法位置，用户中断立即停止后续变更，迟到模型回复无效。
9. 让模型返回过期版本、未知物件 ID、无权物件、重复请求；错误不造成额外变动，重复成功请求返回同一事务结果。
10. 保存失败和提交后立即退出分别验证：前者原布局完整保留，后者重启恢复已保存布局；不能出现一半家具新、一半家具旧。
11. 居民回执为已提交后，再执行一次实际物件活动；规划或提交成功与活动真正完成分别记录。
12. 退出装修后托盘、阴影辅助和轮廓全部隐藏，恢复用户原先选择的观察镜头模式，不影响播放器或聊天入口。
