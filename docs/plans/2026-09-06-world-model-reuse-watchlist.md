# 世界模型与素材技术复用计划

研究日期：2026-09-06。建议下次人工复查：2026-09-20，或下文触发条件提前满足时。本文没有创建定时任务。

状态：官方公开资料核对与仓库接口检查完成；新增模型未部署、未实测，也未购买云服务。DGX 上的图片转道具服务由素材子任务负责，本研究不占用其 GPU。

## 1. 决策摘要

主线仍是居民能观察环境、自主选择活动、使用物件、接受引导和中断。生成、感知、编辑、动作与录制负责增加居民可做的事；主线不等待某个未来世界模型发布。

本轮分为三组：

| 分组 | 范围 | 当前决定 |
| --- | --- | --- |
| 直接复用 | 已采用的 Marble 生活舱、SPZ＋碰撞 GLB、现有动作工厂、VRM／PMX／VMD／VRMA 管线 | 保留现有客户端；把新资产接进当前物件与活动接口，不重新做渲染引擎或生成模型 |
| 做小样验证 | 在建的 TRELLIS.2 道具服务；之后按需求试 WorldMirror 2.0、HY-Motion 1.0、UniRig；空间布局受限时试 Marble Chisel | 一次验证一段链路，先用现有房间和少量资产，记录失败与人工修复成本 |
| 只跟踪 | HY-World 2.0 完整世界生成、Hunyuan3D Part、Buffalo 1.0、WorldClaw、WorldPlay／Voyager、AMI Labs、物理强化学习 | 有明确接口、可用产物和主线需求后再提升优先级；论文或演示不计作已接入能力 |

这是当前工程安排，非供应商质量排名。中文文档按中文排版技能统一格式；技术研究按“先查官方状态与停服公告，再判断适用范围”的方式进行。

## 2. 技术链与验收边界

同一件素材可以经过多段加工，每段保留独立产物和来源：

```text
参考图／文字／视频
  → 房间生成 或 单物件生成
  → 几何与材质整理、尺度与原点校准
  → 静态物件：碰撞体＋放置面＋交互点
    可动角色：骨骼＋蒙皮＋人形骨骼映射
  → 现有动作 或 新生成动作 → 重定向、接触和循环校验
  → 物件／动作／活动包 → 居民发现并调用
  → 真实运行结果 → 镜头与录制 → 用户选择分享
```

| 能力 | 模型可提供的候选结果 | gmgn 必须确认的事实 |
| --- | --- | --- |
| 空间感知 | 深度、法线、相机、点云、物体区域与语义 | “那里可能有椅子”与已登记的可坐椅子分开；结果附来源和置信信息 |
| 几何计算 | 重建网格、建议路线、估计尺度 | 实际地面高度、门宽、胶囊碰撞、通路、交互点可达性；以正式几何查询为准 |
| 生成 | 网格、材质、SPZ、全景、动作或视频 | 资产能否解码、尺寸是否合理、设备能否承受、角色能否实际使用 |
| 编辑 | 改外观、补区域、分割部件、提议布局 | 独立物件身份、位置、旋转、碰撞、导航、存档一致更新，可预览和撤销 |
| 行动与规划 | 选择目标、动作序列、预估行动后果 | 工具返回决定已发生什么；用户中断立即影响后续行动，旧结果不得覆盖新状态 |

图片或视频中的自由漫游，不保证有稳定的物体 ID、可存档的库存或精确碰撞。可导出网格也不保证自动拥有开关、拿取、坐下等行为。可动角色还需要骨骼、蒙皮、动作映射；生成网格不能直接称为可用 VRM。

| VRM Animation＋当前 VMD 适配 | VRMA 标准覆盖人形骨骼、表情和视线；当前仓库有 VMD 到 VRM 适配 | 优先使用已有合规 VRM，统一骨骼语义和参考姿势；新绑定结果先过适配再进入动作库。动物与机械件可走独立 GLB 节点动画，无需强制套人形。[VRMA](https://vrm.dev/en/vrma/)、[现有适配](/Users/ghostcorn/dev/gmgnradio/apps/macos/Sources/GMGNRadio/MMD/VMDToVRMClipAdapter.swift) |

骨骼、蒙皮、重定向须分别验收：关节是否完整；弯肘、抬臂是否撕裂；脚底与地面是否稳定；目标角色身高变化后手能否到达交互点；取消时能否平顺退出。咖啡杯、唱片等刚体优先使用位置与握持点，无需先自动绑定全套骨骼。

舞蹈的歌曲、人物动作与镜头轨道作为可替换素材，通过统一时间轴播放。生成模型产生一段骨骼动作，不意味着已经具备配乐、节拍同步或摄影设计。这些仍由演出包和播放器协调。

### 5.1 当前生活舱的尺度经验需要保留

本地生活舱记录已采用 Marble 1.1 的真实生成资源，同时对门高与碰撞网格做了人工尺度校准；它已经说明生成建筑内部比例并非处处一致。[生活舱记录](/Users/ghostcorn/dev/gmgnradio/authoring/worlds/marble-living-cabin/README.md)

本次官方 SPZ 渲染文档给出米制系数、地面偏移和独立坐标轴转换；发布记录又区分 Studio 导出和原始资产约定。不要把不同来源的文件统一再翻转或缩放一次。新资产要保存导出途径、格式版本、原始坐标约定及采用的变换；用已知长度和地面点验证，避免直接替换当前已校准生活舱的参数。[SPZ 渲染说明](https://docs.worldlabs.ai/api/rendering-spz)、[导出规格](https://docs.worldlabs.ai/marble/export/specs)、[发布记录](https://docs.worldlabs.ai/marble/release-notes)

特别待验证：当前生活舱以源坐标原点再缩放，官方现行示例则先缩放中心、再减地面偏移；本次只登记两种记录的语义差异，没有证明当前实现错误，也没有修改它。需用固定原始包、元数据与实际地面测量比较。

## 6. 近期只展开这三个验证节点

### 节点 A：生成道具进入现有房间

依赖：素材子任务能返回真实任务结果和可下载网格；居民主线已有物件／活动发现入口。

1. 使用有权使用的三类参考图：刚体装饰花盆、细杆椅子、带操作面的咖啡机。先验证外形与摆放，咖啡机行为用明确的活动模板。
2. 记录原始输入、模型与权重版本、生成参数、产物哈希、耗时、失败原因；保留原始结果，另产客户端用的轻量 GLB。
3. 校准尺寸、底部原点、正面方向，检查材质、纹理引用、三角形数和碰撞代理。生成质量不足就列为待修，不把坏结果发布给居民。
4. 在现有生活舱里预览、移动、旋转、撤销和保存；调整道具后，用真实导航确认居民能走到操作点，更新后旧操作点不得继续生效。
5. 让居民发现新物件、选择可用活动、实际使用并接受中断。回执区分“生成完”“已安装”“放置成功”“活动完成”。

通过标准：三类道具各有一个产物完成上述流程；至少一个失败案例被识别且未改变正式房间；有前后帧时／内存对照和产物记录。先用项目已有性能预算，没有数据前不编造统一多边形上限。

### 节点 B：已知房间的几何助手

触发：摆放功能已经可用，但活动点、尺寸校准或遮挡修正仍经常靠手工。优先单独试 WorldMirror 2.0，不先运行整个 HY-World 2.0。

固定一个有已知相机和几何真值的小场景，提供少量多视图图像及明确尺度。对比地面、墙面、门洞和桌面预测；随后用我们自己的射线、碰撞和可达测试确认。若样本来自现有生成场景，要注明是对生成画面的重建，不能据此证明真实空间理解准确率。

通过标准：能解释误差与人工修复量，相比当前手工确有节省；最关键的门洞和活动点不得仅凭视觉猜测通过。导航网格工具有需求时优先评估现成 [Recast／Detour](https://github.com/recastnavigation/recastnavigation)，暂不为“可能需要”替换现有导航。

### 节点 C：动作增量与演出包

触发：居民会选择活动，但缺少动作导致活动表现重复。先接现有动作工厂；新模型只试少量短动作，保持现有角色与房间不变。

同一动作对两种身高 VRM 试播，检查脚底、手部目标、根节点移动和中断过渡。已有动作无法覆盖时，再选 HY-Motion 或视频运动恢复；新增未绑定角色出现后才试 UniRig。演出包追加音乐与镜头，录制采用本地实际画面和明确授权音轨，避免把供应商预览作为真实体验录像。

通过标准：动作可以安装、选择、播放、打断并恢复；音乐／动作／镜头暂停与恢复同步；手机比例的短片可由用户预览后分享。戏剧演出先复用这些能力，暂不建设多人实时生成导演系统。

## 7. 强化学习的后续位置

适合研究的问题是动作如何适应不同高度的椅子、避障和接触等反复出现的控制难题。当前居民选择活动、使用工具、处理失败和接受人类引导，仍由通用循环承担。播放固定动画也继续保留，适合成本稳定的生活动作和编排演出。

可跟踪 [NVIDIA ProtoMotions 3](https://github.com/NVlabs/ProtoMotions) 的数字人运动模仿／控制，以及其使用的 [Isaac Lab](https://github.com/isaac-sim/IsaacLab) 仿真框架。公开学习框架不等于适配 Metal／VRM 的现成控制器，物理骨架、质量、关节限制和碰撞需另外建模。供应商模型曾使用 RL 训练，也不意味着我们当前接入必须自己训练。

启动任何 RL 小样前，以下条件同时满足：

- 有可复位、可重复的隔离测试环境和固定时间步，模型可观测内容及动作接口定义清楚。
- 有固定动画＋导航／逆向运动学基线，能够指出其可量化缺陷，而非单纯追求“更智能”。
- 奖励、终止、失败和中断规则能独立评估，至少覆盖成功接触、穿模、跌倒、耗时和越界，不用视觉好看作为唯一奖励。
- 示范动作与训练数据来源、生成输出许可均允许该用途；人体模型、动作集和框架的许可证分别记录。
- 已测单环境和并行环境显存、训练吞吐、评估时长及最大预算，给当前素材服务保留资源；DGX 空闲与否由实际部署负责人确认。
- 策略只在隔离副本中训练，不能操作用户真实房间、付费接口或个人文件。先离线评估，之后受限接入；可暂停、撤销并返回已有控制方案。

目前仅登记技术方向，不启动训练。首个候选任务应限于一个可量化接触动作，不做开放世界综合奖励，不把用户日常生活当在线探索场。
