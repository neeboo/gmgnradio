# Marble 生活舱与独立物件实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 用用户确认的宽敞生活舱参考图生成真实 Marble 环境，在同一空间内渲染独立物件并完成一次实际交互。

**Architecture:** 舱体使用 Marble SPZ，角色与物件独立实时渲染。生成结果的编号、尺寸校准、碰撞、活动点及存档属于同一个空间包，不再用本地方块舱替代生成背景。先采用一个通过检查的空间，不建设完整编辑器或市场。

**Tech Stack:** 现有 macOS Metal / SceneKit、WorldRuntime、World Labs API、SPZ 与 GLB。

## 已确认的设计

- 视觉基准为用户 2026-09-05 提供的宽敞生活舱图：浅色舱壁、窗外星球、暖色间接灯、充足中央活动面积。
- 生成输入去掉人物与独立圆柱物件；保留固定舱壁、地板与平台。角色、咖啡机或点唱机不能烘焙进背景。
- 优先沿用真实米制校准，避免再把不同房间统一缩成约 4 米的展示盒。
- 本轮生成一次标准世界，不自动重复付费提交，不采购高精网格导出。结果失败或余额不足时明确报告，不换成几何占位房间冒充完成。
- 不使用电脑界面自动操作，不读钥匙串，不并行跑构建。保留前一轮尚未提交的入口修复。

## 任务 1：参考图和可复用生成流程

**Files:** `authoring/worlds/marble-living-cabin/`、`tools/marble/`。

1. 用图像编辑工具去除人物和前景圆柱，保存原图与无人物生成输入。
2. 先测试上传请求、生成请求、操作编号持久化及恢复行为，使用本地网络替身，不调用付费接口。
3. 实现上传 → 单次提交 → 按操作编号恢复查询 → 下载 SPZ、碰撞 GLB、缩略图与来源记录；密钥只在内存用于官方 API，不写入日志或资产。
4. 读取余额并提交一个标准图生世界；遇到不确定提交结果不自动重发。
5. 检查生成图、尺寸元数据及资源，记录实际耗时、编号与质量层级。

## 任务 2：统一生成环境与客户端空间包

**Files:** `App/LivingWorldBootstrap.swift`、`App/GMGNRadioApp.swift`、`VisualEngine/MarbleWorldLibrary.swift`、`Resources/Worlds/` 及对应测试。

1. 添加生成房间按明确编号/本地资源进入的失败测试，覆盖本地占位舱不抢占、旧异步下载不覆盖当前空间。
2. 加载已采用世界包及对应 SPZ；同一包提供实际尺寸、出生点、镜头和独立物件活动点。
3. 保留既有旧空间文件作为参考，不破坏已有存档；新空间用独立版本。
4. 运行不启动应用宿主的合同测试，确认资源路径可解码且没有占位背景回退。

## 任务 3：独立物件融合

**Files:** `MMD/PMXStageAvatarRenderer.swift`、`VisualEngine/Metal/MarbleSpatialView.swift`、`VisualEngine/SpatialStageStore.swift` 及对应测试。

1. 先测试物件与舱体分离、只在对应空间显示、米制位置和活动点一致。
2. 在 SPZ 背景上渲染一个独立设备，不清空环境颜色；不渲染旧舱壁/地板。
3. 选择一个已有活动，使角色走到设备、产生动作并触发真实结果；本轮优先点唱机与现有播放器连接。
4. 验证正常完成、取消和失败不重复触发；不同空间不串状态。

## 验收与交付

- 明确区分生成成功、包导入成功、渲染成功、可交互成功，不能用测试数量代替可见结果。
- 生成环境中没有固定 2B；实时角色和设备使用同一比例、同一地面与可达位置。
- 可复用保存的输入与命令重做一个新房间，正式记录本次生成来源。
- 如需构建，单任务低优先级；安装仍只到 `/Applications/gmgn radio.app`，不留重复应用。
- 本轮未完成的实际体验检查明确列出，不承诺已实现自由装修或完整自主生活。
