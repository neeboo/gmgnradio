# 回复延迟与图文恢复：修复及宿主复验

前次记录：[消息补收与原委托自动恢复](2026-09-07-host-e2e-fixes.md)。本轮继续使用同一生活舱、同一咖啡机与原参考图，没有新增生成任务，也没有直接修改业务数据库。

## 结论

- 三条简短文字回复均已在宿主显示，首模型请求至最终回复完成分别为 **7.417、2.723、1.526 秒**，实际配置均为 `low / 8192`。
- 在旧回复进行中排队发送图片与文字，点击停止后，原文字和图片共同恢复到输入框；没有自动重发。
- 手动重发时发现图片回复包含未转义换行，随后补齐受限格式处理；最终构建用同图、同提示词重测，界面成功显示“图片已收到”及咖啡机描述。
- 最终读回仍为 **1 个任务、79 条消息、237 个确认记录**，即界面、场景、居民各确认 79 条。咖啡机仍在原展示台，布局版本保持 4。

## 修复范围

### 默认回复延迟

居民文字通道通过应用私有插件，在模型选择完成后读取已解析设置，仅在未显式指定推理档位时补 `low`。显式档位、关闭推理和其他模型提供方保持原行为。

没有修改全局 DSH 配置、模型、凭据或 300 秒限制。私有目录权限为 `0700`，配置与插件文件为 `0600`；每次执行前检查类型、路径和完整字节。组合配置只额外允许该固定模块，原工具禁用规则保持不变。

### 停止后的未送达图文

停止先取消当前执行并清空队列，再把尚未送达的提交返还给原输入面。保留原图片身份、文字和较新的草稿；校验循环身份、空间与会话范围。已送达、执行中或送达状态不明的输入不会回填，避免重复操作。失效和跨空间提交不回填。

图片仍按顺序等待旧轮结束，不抢占正在进行的后台事务；现在可停止旧轮、取回图文，再由用户手动发送。

### 图片最终回复的换行格式

16:14 的真实失败中，原生通道收到 `[image, text]`，模型正常识图。首次自然文本触发格式纠正，第二次 `final/text` 信封的文字里仍有 9 个未转义换行，导致严格解析失败。

修复仅接受精确 `type/text` 两字段最终文字信封中的原始 LF/CR，再做严格 JSON 校验。工具调用、未知或重复字段、嵌套、其他控制字符、截断与非法转义仍拒绝。纠正提示同时明确换行转义要求。

### 图文实测步骤

1. 发送一段明确禁止工具和任务修改的较长文字回复请求，用于维持旧轮进行中。
2. 添加原咖啡机参考图并发送描述要求；界面显示“1 条消息排队中”。
3. 点击停止，文字和图片共同恢复，并显示“未自动重发”。
4. 手动发送后发现换行格式问题，图文仍被保留；记录失败现场，再修复及重新构建。
5. 在最终构建中重新添加同一原图，发送同一描述要求，成功显示图片描述；没有生成、领取或摆放操作。

最终图片轮使用 `vision-exp / low / 8192`，输入 1 个图像块、工具调用 0 次；16:26:37.387 至 16:26:51.902，共 14.515 秒，含一次格式纠正。此次最终返回严格合法 JSON，没有原始 LF/CR，实际走严格成功路径；换行归一化分支由脱敏的真实失败结构回归覆盖，不记为本次宿主实际命中。

最终使用的构建位于 `apps/macos/Build/Build/Products/Debug/gmgn radio.app`。本轮没有覆盖 `/Applications` 安装版，没有请求新的系统权限或访问钥匙串。最终调试动态库 SHA256：`3ae92b230e2501d3ba293ec11288e17b4690d805f43138a5bb09cb2dffd6b5df`。
