## Codex 通道选择依据

初次检查时实际聊天定位器优先命中 `/usr/local/bin/codex`，版本 `0.145.0`，环境中另有 `0.147.0`。现已按用户要求将这两份 CLI 更新为 `0.153.4`，详见文末修复记录。下述源码核对记录保留初次验证版本。

已通过本机离线协议生成确认：`thread/start.dynamicTools`、`item/tool/call`、`turn/interrupt` 可用；工具定义要求 `type: "function"`。新建和每轮请求的 `environments: []` 均有禁用环境访问的协议注释。旧 `exec` 会话不能通过续聊补入动态工具，需要独立的居民工具会话。

已采用应用内双向通道，将正式调用交给现有 `WorldAgentToolDispatcher`。这不需要把普通回答解析成命令，也不需要部署另一个 MCP 服务。动态工具为实验性协议，具体字段以本机版本为准。[官方说明](https://learn.chatgpt.com/docs/app-server)

此前权限核查阻止了真实测试：空环境是否同时限制用户配置的 MCP、插件和钩子不能仅据参数名称判断；只读沙箱也不代表禁止读取和执行命令。该问题已通过下述独立进程配置预检解决，不能删掉预检而只保留四个动态工具。

源码补查已证实空环境会移除本机命令、文件修改和图片查看等处理器，但外部工具另有来源；`mcp_servers = {}` 的深度合并不会清除原有配置。不能将这两个参数的组合视为完整隔离。

核对的是实际安装版本对应的官方 `rust-v0.145.0` 源码，关键证据：

- [空环境的工具测试](https://github.com/openai/codex/blob/rust-v0.145.0/codex-rs/core/src/tools/spec_plan_tests.rs#L623)：本机 shell、exec、apply_patch、view_image 等处理器不注册。
- [MCP 工具组装](https://github.com/openai/codex/blob/rust-v0.145.0/codex-rs/core/src/tools/spec_plan.rs#L590)：普通 MCP 不受上述空环境条件限制。
- [配置深度合并](https://github.com/openai/codex/blob/rust-v0.145.0/codex-rs/config/src/merge.rs#L11)：空表不清除已有服务器。
- [旧通知钩子](https://github.com/openai/codex/blob/rust-v0.145.0/codex-rs/hooks/src/registry.rs#L61)：应另设 `notify = []`，不能仅关闭新 hooks 功能。

关闭插件、Apps、钩子、通知、协作、网页搜索和图片生成，仍不能单独解决普通 MCP 的继承问题。`mcpServerStatus/list` 可能启动连接，因此没有使用。`config/read` 的完整响应只在进程内短暂解析，提取工具服务名称后丢弃，不输出、不保存响应或其中的配置值。

### 当前采用：配置预检加逐项禁用

`ResidentCodexPolicy` 与 `ResidentCodexAgent` 按以下顺序运行：

1. 启动应用拥有的预检子进程。启动参数已关闭插件、Apps、新旧钩子、多代理、搜索和图像生成；两种认证存储都强制为 file，不访问钥匙串。
2. 初始化后读取有效配置，只提取 MCP 服务名称；不连接这些服务，也不启动模型。关闭预检进程。
3. 用每项 `enabled=false` 启动新的居民进程，再核查其有效配置。服务名用 TOML 内联表的完整引号键，避免带点的名称被拆成路径。任何已启用服务或不明确的安全开关均阻止线程启动。
4. 使用应用自建空目录，新线程和每轮均指定空环境、禁止批准；清除继承的远程执行入口，保持 `CODEX_EXEC_SERVER_URL=none`。仅注册四项空间工具。
5. 居民工具会话使用独立 `.tools.v1` 保存范围，不续用过去的普通 exec 会话。所有退出路径关闭本次拥有的子进程。

主任务实际运行配置预检通过：11 个外部 MCP 定义在居民子进程中被禁用。全局设置、登录文件没有改动或复制；没有启动应用或测试宿主。随后仅做线程握手检查，也确认实际版本接收四个工具，无模型轮次。

依据：[配置读取实现](https://github.com/openai/codex/blob/rust-v0.145.0/codex-rs/app-server/src/config_manager_service.rs#L130)、[插件启动开关](https://github.com/openai/codex/blob/rust-v0.145.0/codex-rs/core-plugins/src/manager.rs#L1968)、[文件认证不回退钥匙串](https://github.com/openai/codex/blob/rust-v0.145.0/codex-rs/login/src/auth/storage.rs#L514)、[点分隔覆盖参数](https://github.com/openai/codex/blob/rust-v0.145.0/codex-rs/config/src/overrides.rs#L20)。本轮核对本机下载的对应官方版本源码。

### 已放弃的候选：独立 exec + 应用自己的 MCP

进一步源码核查找到 `CODEX_EXEC_SERVER_URL=none`，可配合 `exec --ignore-user-config --ignore-rules` 禁用本机环境并忽略用户工具配置；原有登录目录继续由 Codex 正常使用，不需要应用复制认证信息。[命令参数](https://github.com/openai/codex/blob/rust-v0.145.0/codex-rs/exec/src/cli.rs#L34)、[无环境实现](https://github.com/openai/codex/blob/rust-v0.145.0/codex-rs/exec-server/src/environment_provider.rs#L94)

该方案需要应用新增一个仅供居民进程连接的世界工具服务，复用既有四项世界工具。执行目录使用应用自建空目录，过滤继承的远程执行环境变量，显式关闭额外功能与通知钩子。

忽略用户配置不会同时忽略系统／管理配置，不能承诺所有机器都只剩应用工具。[加载顺序](https://github.com/openai/codex/blob/rust-v0.145.0/codex-rs/config/src/loader/mod.rs#L222) 此候选没有实现。当前有效配置复核方案已覆盖这些来源，无需新增世界 MCP 服务。
