# 播放器、空间与角色控制入口梳理

## 结论

现有能力大部分仍在，入口简化没有完成相应的功能迁移。动作快捷菜单和生活活动存在明确断链；播放器视觉选项仍可由底部六边形图标打开，但辨识度差，切到空间后被模式规则隐藏。本次先完成只读审计，不据此改写全部界面或动作运行逻辑。

## 已有能力及断点

| 能力 | 现状 | 证据 |
| --- | --- | --- |
| 字幕特效 | 12 种模式仍在，仅播放器面板可达 | StagePresentationModel.swift:494；StageOverlayView.swift:2104 |
| 点阵与粒度 | 8 种选择，粒度可持久保存；空间不渲染该播放器表面 | StageVisualPresetTimeline.swift:16、318；StageOverlayView.swift:2122、2142 |
| MV | 导入、单次/循环/随机拼接、关闭、亮度和歌曲绑定仍在 | StageOverlayView.swift:2171–2282 |
| 角色与动作资产 | 模型切换、动作导入/播放/删除、远端动作目录仍在全局设置“角色”页 | Settings/PresenceSettingsView.swift:14–70、155–172 |
| 快捷动作播放 | 处理函数保留，当前前台菜单不消费 | App/GMGNRadioApp.swift 的 CharacterMotionMenuPolicy、playCharacterMotion |
| 生活活动 | 世界包注册了活动列表，当前前台菜单不消费 | App/GMGNRadioApp.swift 的 LivingWorldActivityMenuStore、configureLivingWorld |

源码路径前缀均为 `apps/macos/Sources/GMGNRadio/`。行号以本次检查为准。

`StageVisualPickerMode` 将空间内容硬限制为“空间选择、人物位置、加载状态”，播放器限制为“字幕、点阵、颗粒、MV”。两边都没有就近的动作入口。历史提交 `1e0cdec` 引入该模式分组。

底部视觉按钮只显示 `circle.hexagongrid` 图标，区别仅在悬停提示。选择面板固定为 590×458，内部没有滚动容器；尚未通过真实界面证实裁切，但扩展选项时不能继续依赖固定高度。

## 恢复后的入口归属

| 所在位置 | 即时控制 | 保留边界 |
| --- | --- | --- |
| 播放器 | 画面：字幕、点阵、粒度、MV；角色动作：已安装兼容动作、待机/停止 | 不需要为了选动作进入全局资产管理 |
| 空间 | 空间：当前环境、人物位置、镜头复位；角色动作；生活活动：散步、点唱机等正式活动 | 活动来自当前世界包，不硬编码不存在的设施 |
| Live Cam | 保持聊天、语音、播放器、空间、设置入口；可提供角色动作快捷入口 | 复用同一个角色和动作状态，不创建另一套角色 |
| 全局设置 | 角色/动作导入安装删除，账号，模型与语音服务，默认空间，快捷键 | 长期配置与当前画面即时控制分开，但互相有入口 |
| 系统驻留菜单 | Live Cam、空间、播放器、设置、退出 | 继续保持简洁，不把功能全部堆回驻留菜单 |

恢复时保留现有选择器与状态模型。按钮使用可读名称；面板按分区组织并可滚动。需要跨模式查看选项时明确注明作用范围：播放器点阵和 MV 当前属于播放器渲染，不能在空间面板放一个点击后不影响当前画面的无说明开关。

## 动作执行的判断边界

设置选动作已有“停止当前活动 → 激活动作 → 刷新角色”流程；待机状态保留用户选中的动作。没有证据证明所有手动动作都会被自主活动覆盖。因此优先恢复入口，不改既有动作优先级。若实际点击仍无动作，再逐项核对格式兼容、加载失败和活动停止结果。

## 实施顺序与验收

1. 先恢复播放器和空间的角色动作入口、空间的生活活动入口，调用现有执行函数。
2. 保留完整播放器视觉功能，将六边形图标改成明确的画面/空间控制入口。
3. 复用资产管理入口，处理面板滚动与较小窗口布局。
4. 逐项验证“可发现 → 可打开 → 可选择 → 实际生效 → 模式切换后状态保留”。动作还要验证能停止当前活动、正确识别角色格式，不引发窗口跳转。

本轮未使用桌面自动化，也未据代码存在就宣称真实点击验收通过。

## 装机后的反馈与修订（2026-09-05）

`5b0ed40` 随后已安装至 `/Applications/gmgn radio.app`。用户实际使用后要求：空间底栏的“设置”也应可访问播放器配置，同时改进底栏和面板的外观。本节取代上文按当前画面隐藏设置分区的设计。

修订范围：

- 同一个入口固定提供“播放器 / 空间 / 角色 / 活动”。浏览分区与当前画面独立，选择播放器设置不触发离开空间。
- 播放器分区始终提供现有字幕、点阵、粒度和 MV 配置，并注明这些效果作用于播放器画面。
- 活动分区保留当前世界可见且 ID 一致的执行条件；统一入口不扩大活动可操作范围。
- 底栏采用稳定的深色背景和更清楚的功能分组，减少竖线，保留按钮点击区域；设置使用常规图标和紧凑文字排布。
- 面板统一标题、间距、选中状态和对比度，继续保持滚动、小窗边界和共享状态。只调整底栏及其设置面板，不扩展至房间、角色渲染或全局页面重构。

验收：两种画面中都能访问四个分区；分区切换不切换实际画面；播放器配置仍调用原有状态；活动不能串到其他世界；设置开关、播放控制、镜头及空间进出回归通过。真实视觉效果单独记录，不用代码测试代替界面验收。

实施与验证结果：

- 已实现固定四分区，播放器控件保留原有状态绑定；用户选择分区后，不随实际画面切换重置。
