### 物件：只从素材生成 + 三轴尺寸
- **手拼几何那条路彻底停用**（`WorldPrimitiveTelevision` 保留类型、产品路径**零调用**），并配了门禁：谁把它加回来/给出"重新生成 or 用几何拼"二选一，测试当场红（`tools/test-generation-only-props.swift`）。
- **三轴契约**：`size_intent {mode:"dimensions", millimeters:{x,y,z}}` ⇒ 世界 `size` **逐轴**等于 `(x/1000, y/1000, z/1000)`；**渲染与碰撞盒读同一组数**；只给一个数时仍是"最长边等比"。
- 修掉的错：`edges.max() ?? 0 / 1000`（**毫米被当成米**，1443 米 ⇒ "尺寸无效"）；失败记录把托盘**永久锁死**（改成现场推导说了算、记录只提供原因）。
- **"厚度不对"的真相**：三个数**分毫不差**（1.443 × 0.862 × 0.302，四条渲染路径实测 0 偏差，用户截图也被拿去几何反推验证过）。那 30 厘米是**整块实心方块**的厚度 —— 因为生成器交回来的是**立方体**。真电视的 302 mm 是**底座进深**、面板只有几厘米。**这是生成侧/产品语义问题，不是尺寸链**；立方体靠缩放变不出面板。

### 电视屏幕
- 覆盖层 = 原生 `WKWebView` 对齐到物件的屏幕四边形（每帧投影 + 透视变换）；**按格遮挡**（与渲染器同一份房间三角面，24×14 格，mask 层）；背向剔除；默认**不吃鼠标事件**（14 条输入链的红线）。
- **屏幕铺满正面**：写死的 86% 内缩换成"跟着这一面自身尺寸走的边框余量"（最短边 1%）：覆盖 **73.96% → 96.83%**，真机实测边框 9 mm。
- **对齐口径**：`NSViewBackingLayer.anchorPoint` 恒为 `(0,0)`，而我们按"绕层心"解算 ⇒ 差一次**共轭** `G(q) = a + H(q−a)`（**不是**把 `m41/m42` 归零，那样更差）。偏差 **24.6 px → 0.00009 px**。
- **AppKit 会在改 `frame`/`frameOrigin` 之后把 `layer.transform` 重置成单位阵** —— 于是"变换没变就早退"在尺寸被滞回固定住之后**永远命中**、变换永久停住。修法：**读图层现值，不等就写回**。
- **嵌入播放**：以前是**顶层直载** `embed` 页 ⇒ 没有"嵌它的页面" ⇒ YouTube **153** / Twitch **NoParent**。改成**承载页 + 官方 iframe**，承载页 origin 是**回环地址的随机高位端口**、**故意不开任何监听**（比开小服务更安全，渲染结果逐字节相同）。
- **播放不起来的真根因**：**我们自己**在链接上追加了 `autoplay=0` ⇒ 页面加载好、等你点、而覆盖层又收不到点击。现在播放参数**只有一个出口**（`WorldScreenEmbedOrigin.officialPlayerParameters`）：YouTube/B站 `autoplay=1`（**不静音**），Twitch 补官方要求的 `parent=<回环域>`。实测 B 站前进 19.26 s、YouTube 16.31 s。
- **性能**：爆卡主凶是**我们每帧改宿主尺寸** ⇒ WKWebView 每帧重排重画（跨进程）。渲染尺寸改**带滞回**（相机移动全交给单应矩阵）：换尺寸 **120 → 3 次/120 帧**，我们这侧每帧 **0.63 → 0.27 ms**；掩码 23 Hz 节流、同一张掩码不重建路径。
- **「操作屏幕」模式**（用户要能偶尔点网页按钮）：底部控制条上一个图标，**默认关闭**（不点就与以前逐字相同）；进入后覆盖层才收鼠标、出现「正在操作电视，按 Esc 退出」；**Esc** 或再点一次退出。指针让路发生在 **AppKit 的 hitTest 层**，所以"谁吃指针"的判据**仍然只有一处**（`consumesScenePointer` 一字未改）。
- 已知：**Twitch 的自动播在本机测不出来**（播放器不请求流）；**B 站黑屏**与来源无关（包不包装一样）。

## 2. 纪律与教训（踩过的坑，别再犯）

1. **断言必须能失败**。今天的重灾区是"自证的假绿灯"：屏幕对齐那条断言读的是我们自己写下的中间量（按构造恒为 0），跟 CoreAnimation 真正画在哪无关；一条负对照因为现场缺数据而**空转**（永远绿）。**每条断言都要能证明"注入就红"。**
2. **不要手抄替身**。harness 里的手写替身会漂移（漏了 `isFinite` 守卫、签名少一个参数）。能抽**真源码切片**就抽真源码。
3. **一处定义**。尺寸（`effectiveSize`）、状态（唯一投影）、文案句（`OwnershipSentence`）、退避（`RetryBackoffSite`）、播放参数（`officialPlayerParameters`）、指针裁决（`consumesScenePointer`）——今天所有大 bug 都是"第二份真相"。
4. **派生结论不许落盘 / 不许当事实**。失败记录曾经把托盘永久锁死；收件箱的已读若不落盘就会每次重启变未读。
5. **不许静默**。拒绝要具名（哪个挂点、哪一腿、哪个字段、期望与实际），失败要说人话，细节进日志。**按钮不许撒谎**（做不到就不给那个动作）。
6. **提交只在构建绿的时候做**；门禁红时要逐个区分"我的 / 别人在制 / 数据漂移 / 真回归"。今天多次用 `git add -A` 把别人未完成的改动卷进提交（包括我自己），**别人多线并行时不要用它**。
7. **不要 `git mv/rm/checkout/restore/stash`**；不要在带符号链接的树上 `rm`；注入还原用**唯一锚点的逐字 edit + sha256 校验**。
8. **多线并行会撞车**。今天有 4–8 条线同时改同一批文件，反复出现"编到一半的红"与"互相覆盖"。派活时**明确落点文件**，重叠处只做最小插入，冲突先报告。
9. **量具会骗人**：不在窗口里的离屏 `WKWebView` 连最简视频都不播；`log show` 宽时间区间不可靠；关键证据常常在**居民的 DSH 会话账本**里。
